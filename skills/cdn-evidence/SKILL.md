# CDN 故障采证

按以下顺序完成诊断，不要跳过证据直接给根因：

1. 从用户输入和内部意图路由元数据中确认故障类型、设备 ID、时间范围和现象。缺少设备 ID 或关键现象时，只询问缺失信息。
2. 先列出需要验证的 2 到 4 个假设，并为每个假设选择最小的只读证据集。
3. 优先使用只读命令采证，例如 `date`、`uptime`、`df -h`、`free -m`、`ps`、`systemctl status`、`journalctl` 和网络只读查询。一次尽量取齐相关证据。
4. 将工具结果按“已确认 / 已排除 / 仍待验证”整理。只有直接证据支持时才把某项写成已确认。
5. 需要处置时，先说明动作、原因、影响和风险，再调用受人工审批保护的工具。审批被拒绝后，根据拒绝理由调整方案，不要原样重试。
6. 最终回复先给结论，再列关键证据和下一步。工具数据标记为 mock 时必须明确说明，不得把 mock 当作真实节点事实。

遇到命令超时时，将执行结果视为未知；使用只读命令核实实际状态，不要立即重复同一个变更命令。
