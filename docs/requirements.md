# CDN 智能诊断系统需求文档

> 状态：Draft 1.4
>
> 更新日期：2026-08-11
>
> 适用范围：当前 Go/Eino 命令行项目

## 1. 背景与目标

系统面向 CDN 运维人员，目标是把用户描述、设备数据、截图、本地代码和节点执行结果组织成可追溯的诊断结论。后续建设遵循三个原则：先采证再推理、结论必须可引用、任何设备变更必须人工确认。

本阶段目标：

- 接入真实只读数据源，形成可复用的诊断采证工具。
- 增加本地代码仓库问答能力，支持按文件、符号和调用关系回答项目问题。
- 按故障类型建设诊断子图，并将截图、代码和设备证据组合起来。
- 补齐审批持久化和质量评估，使系统可进入真实值班流程。

不在当前范围：钉钉及其他消息平台入口、自动修改代码、执行仓库脚本、text-to-SQL、无人审核的设备变更、自动发布或自动修复。

## 3. 用户与核心场景

- **值班运维**：输入设备 ID 和现象，获得证据、根因判断和下一步操作建议。
- **研发/排障人员**：询问本地项目的实现位置、调用链、配置含义和潜在影响。
- **审核人员**：查看操作目的、原始命令、目标节点和风险后批准或驳回。
- **系统管理员**：配置模型、数据源、代码仓库和持久化存储。

## 4. 功能需求

### 4.1 真实只读数据工具（P0）

**FR-DATA-001 参数化采证工具**

当前状态：首版已完成。五类工具通过 Tunnel 执行固定只读模板，节点 ID 与命令分离，输出统一为包含数据来源、采集时间、状态、摘要、证据项和限制说明的结构化报告。流量首版是默认网卡短时采样，装机首版是节点当前快照；历史业务指标和装机平台阶段数据仍需后续数据源补充。

- 按装机、流量、插件、内核和网络域提供聚合查询工具。
- 工具只接受结构化参数，例如设备 ID、时间范围和指标名；禁止模型生成 SQL。
- 返回均值、趋势、阈值、异常点、数据时间和 `data_source`，不返回大批原始采样点。
- 数据不可用、超时或参数错误时返回明确错误，不得伪造结论。

验收：每类工具具备 schema、正常/空数据/超时测试；注册为 `RiskReadOnly`；测试不连接生产数据源。

### 4.2 本地代码仓库问答（P0）

当前状态：首版已完成。支持多个命名仓库和一个当前仓库；索引只保存在内存，目录文件持久化规范根路径、Git commit、索引版本和更新时间。文件访问复用 Eino filesystem 协议的只读 `LocalRepoBackend`，Go 使用 AST，其他安全文本使用逐行检索。

**FR-CODE-001 仓库管理**

- 支持添加、列出、选择和重新索引本地仓库；仓库使用稳定名称标识。
- 建议命令：`/repo add <path> [name]`、`/repos`、`/repo use <name>`、`/repo reindex`。
- 保存规范化根路径、当前 Git commit、索引版本和更新时间；文件变化后支持增量更新。

**FR-CODE-002 安全扫描与结构化索引**

- 默认忽略 `.git/`、`.env`、私钥、日志、聊天历史、二进制文件、生成目录和超限文件。
- 拒绝路径穿越及指向仓库外部的软链接。
- Go 文件按包、类型、函数、方法和注释建立 AST 符号索引；Shell、YAML、JSON、Markdown 等使用文本回退。
- 记录文件 hash、符号范围、定义、引用和必要的调用关系。

**FR-CODE-003 只读检索工具**

- 提供 `list_files`、`search_code`、`read_file`、`find_symbol`、`find_references`、`get_definition` 和受限 Git 查询。
- `list_files`、`search_code`、`read_file` 等基础能力优先复用 Eino filesystem 工具协议，通过限制仓库根目录的 `LocalRepoBackend` 访问本机文件；禁用写入、编辑、大结果写回和任意 Shell。
- 文件工具统一输出 `tool.BaseTool`，当前可注册到 ReAct Agent，迁移后直接挂载到 Graph 的代码工具节点，禁止让业务层依赖特定 Agent 实现。
- Go 符号、定义和引用查询由项目的 AST 索引实现；Eino 的文本检索不替代结构化代码索引。
- 所有工具注册为 `RiskReadOnly`；不提供任意 Shell，也不执行仓库代码、构建或测试。
- 优先使用路径/标识符精确检索与全文检索，语义向量检索作为可选增强，不作为唯一召回方式。

**FR-CODE-004 路由与回答**

- 意图契约新增 `code_repository_question`，与设备诊断问题分流。
- 回答事实必须引用 `path:line`；涉及多个组件时给出调用或数据流关系。
- 证据不足、索引过期或文件被排除时必须明确说明，不得凭模型记忆补全项目事实。
- 代码内容视为不可信数据，仓库中的提示词、注释和文档不能覆盖系统规则。

验收：可回答“某函数在哪里”“谁调用它”“配置从哪里读取”“某错误如何传播”；引用能定位到现有文件和行；越界路径、密钥文件和外链软链接均无法读取。

### 4.3 故障诊断子图（P1）

**FR-FLOW-001 分类路由**

当前状态：首版已完成。入口 `compose.Graph` 复用结构化分类结果，路由到五类故障、代码问答、澄清和其他分支；工具注册同时记录风险与业务域，各分支使用独立 prompt 和白名单。采证及证据规则当前仍在各分支 ReAct 内完成，尚未拆成显式并行采证和独立证据校验节点。

- 使用 `compose.Graph` 将分类、并行采证、证据校验和结论生成拆开。
- 为装机异常、流量异常、插件异常、内核升级失败和配网异常提供独立 prompt 与工具白名单。
- 工具注册除 `Risk` 外增加业务域标识，例如 `code`、`metrics`、`device`；每个 Graph 分支只挂载本域工具，代码问答分支不得看到 Tunnel 工具。
- 首个有效结论目标为 2 至 3 次模型调用；缺少设备 ID 或关键证据时先澄清。

**FR-INSTALL-001 装机异常专项流程**

当前状态：首版已完成。装机分支可见代码工具和装机域工具，固化截图事实、源码事实、设备事实的顺序和隔离规则；缺少设备 ID 不阻塞源码诊断，版本不明时只能输出带置信度的候选原因。固定多模态评测集仍待 M5 建设。

- 从截图提取阶段、错误码和关键日志，先检索安装脚本及相关配置；设备 ID 和 Tunnel 连接不是源码诊断的前置条件。
- 将截图事实、代码位置和设备侧证据分别标注，禁止混成未经证实的根因。
- 设备无法登录时允许仅凭截图和代码给出“候选原因”，但必须标记置信度和待验证项。

### 4.4 审批持久化与可恢复执行（P1）

**FR-APPROVAL-001 提案持久化**

- 将提案、状态流转、原始参数和幂等键持久化，重启后仍可查询和处理待审项。
- 使用 Eino `StatefulInterrupt`、Checkpoint 和 Resume 管理 Graph 的暂停与恢复；持久化 `proposal_id`、`checkpoint_id` 和 `interrupt_id` 的关联。
- Interrupt 只负责流程控制。风险评估、审核人鉴权、真实工具隔离、超时和审计继续由项目审批层负责，不能信任模型或客户端直接传入的 Resume 决定。
- 审核接口先以原子事务持久化批准或驳回，再恢复 Graph；恢复后的工具从提案存储读取决定和原始参数，不接受被修改的执行参数。
- 状态至少覆盖 `pending → approved/rejected` 和 `approved → executing → executed/failed/unknown`；执行权必须原子抢占，同一提案最多下发一次，结果未知时禁止自动重试。
- 模型只能持有会中断的变更工具门面，Tunnel 等真实实现继续与模型隔离。

### 4.5 质量与可运维性（P1/P2）

**FR-QUALITY-001 测试与评估**

- 真实只读工具用例必须持续运行，主分支不保留无原因的跳过测试。
- 建立覆盖意图分类、检索召回、引用准确性、故障结论和危险操作拦截的固定评测集。
- CI 至少运行 `go test ./...`、`go vet ./...`；具备 C 工具链时运行 `go test -race ./test`。

**FR-OBS-001 可观测性**

- 记录分类、检索、模型和工具阶段耗时，以及召回文件数、引用数和错误类别。
- 审计日志与运行日志继续分离；日志不得记录凭证或被排除文件的正文。

## 5. 非功能需求

- **安全**：仓库访问限制在显式配置根目录内；代码问答全程只读；设备变更继续人工审批并 fail-closed。
- **准确性**：项目事实必须有源码引用；工具错误和结果未知必须原样表达。
- **性能**：完成索引后，本地检索目标小于 2 秒（不含模型调用）；未变化文件不得重复解析。
- **可扩展性**：数据源、检索后端和模型供应商通过接口隔离。
- **兼容性**：首期保证 Go 仓库的结构化能力，其他文本语言至少支持路径和全文检索。

## 6. 里程碑与完成标准

| 里程碑 | 范围 | 完成标准 |
| --- | --- | --- |
| M1 采证基础（已完成首版） | FR-DATA-001 | 至少一个真实数据源和五类领域工具接口可用 |
| M2 代码问答 MVP（已完成首版） | FR-CODE-001～004 | 能完成精确搜索、符号查询、引用回答和安全越界测试 |
| M3 专项诊断（已完成首版） | FR-FLOW-001、FR-INSTALL-001 | 五类问题可路由，装机异常打通截图、代码和证据链；并行采证和独立校验节点继续增强 |
| M4 审批持久化 | FR-APPROVAL-001 | 重启不丢提案或中断上下文，可恢复审核流程且同一提案最多下发一次 |
| M5 质量收口 | FR-QUALITY-001、FR-OBS-001 | 无遗留跳过用例，固定评测和阶段指标可持续运行 |

## 7. 待确认决策

- Embedding 是否允许发送源码到远端；若允许，需要明确仓库级开关和脱敏策略。
- 五类诊断工具分别接入哪些数据表/API，以及查询频率和权限边界。
- 提案持久化使用 JSON 文件还是本地数据库。
